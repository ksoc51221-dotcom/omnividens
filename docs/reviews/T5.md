# T5 adapters: review file (reviewer: T4)

Branch: `agent/t5-adapter`. Tests: `pytest tests/test_adapters.py` (11 pass, fake runner, no real `claude`).

## What it does
- `adapters/base.py`: `Adapter` (name, `available()`, `run(instruction) -> AdapterResult(ok, text, tokens, seconds, error)`), config loading, `check_project`, name validation, pluggable `Runner`.
- `adapters/claude_code.py`: runs `claude -p --output-format json --permission-mode <mode> --no-session-persistence [--model M] [--effort E]` in the project folder. Flags checked against `claude --help` (v2.1.291).
- `adapters/registry.py`: `ALL_ADAPTERS` list; `available_adapters()`, `get_adapter(name)`. A new tool = one file + one list entry.

## Safety
- `project` must resolve (symlinks and `..` followed) inside `allowed_projects` in `~/.reelay/config` (TOML). No allow-list, no project, or outside = refuse, nothing run.
- Permission mode defaults to `plan` (read-only). Config may choose `plan`, `dontAsk`, `acceptEdits` only; `bypassPermissions`/`auto` are refused.
- Task is sent on stdin (never an argv item). Skill goes in as `/skill task`; skill/model validated by regex (can't start with `-`), effort by allowlist, task may not start with `/`.
- Time limit `timeout_s` (default 600). `run()` never raises.
- Adapter takes only `Instruction`, which comes from the user's own chat message, never video text.

## Unsure
- Real `claude -p` JSON shape (`result`, `is_error`, `usage.*`) is from memory of the docs; not run live (costs tokens). Worth one manual run.
- `/skill task` via stdin in print mode: not verified live.
- `plan` mode may make "do this edit" tasks only plan; owner can set `permission_mode = "acceptEdits"`.
- Model aliases are passed as-is (`opus`); the CLI accepts aliases, so no ID mapping.
- Config format (TOML, `allowed_projects`, `permission_mode`, `timeout_s`) is new; T9 installer should write it.

## T4's review of T5 (read all of `reelay/adapters/` + tests on `agent/t5-adapter`; did not run live)

Good: allow-list with `resolve()` (symlink test), stdin for the task, unsafe permission modes refused, regexes block leading `-`, `run()` mostly never raises. Security bar met except as below.

**BLOCKER 1: `~/.reelay/config` format clash with T3.** The bot (`reelay/bot/config.py`) reads simple `KEY=value` lines (`TELEGRAM_BOT_TOKEN=123:abc`). `adapters/base.py` reads the same file as TOML. An unquoted `123:abc` is invalid TOML → `TOMLDecodeError` → `load_config` silently returns `{}` → every run is "refused: no allowed_projects" for any user who has a bot token. Both modules also ignore each other's keys. Fix: put adapter settings in a separate file (e.g. `~/.reelay/adapters.toml`) or ask the orchestrator to pick one format. Also honour `REELAY_HOME` like the bot does. Add a test with a real-looking token line in the same file.

**FIX 1: `_parse` can raise.** Valid JSON that isn't an object (e.g. `[]`, `"x"`, `null`) hits `data.get` → `AttributeError`; a non-numeric `usage` value hits `int()` → `ValueError`. Docstring promises never to raise. Check `isinstance(data, dict)` and wrap token sum in try/except; add tests.

**FIX 2: allow-list entry `"/"` or `"~"` allows everything.** Reject an allow-list entry that is `/` or the bare home folder (or at least document it). Low risk since the owner writes the config.

**FIX 3: timeout leaves grandchildren.** `subprocess.run(timeout=)` kills only `claude`, not processes it spawned. Use `start_new_session=True` and kill the process group, or note the limit in the docstring.

**NIT 1:** no spend cap; consider `--max-budget-usd` from config. **NIT 2:** `Runner` type name also exists in `sandbox/runner.py` with a different signature; fine (separate modules), just don't import both unqualified in T8. **NIT 3:** `available()` with an injected `binary` doesn't check the file exists.

Unverified (agree with your list): real JSON shape and `/skill task` over stdin in print mode. T4's sandbox runner assumes the same JSON fields (`result`, `is_error`, `usage.*`), so one live run helps both.
