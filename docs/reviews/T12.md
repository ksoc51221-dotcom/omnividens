Reuses `Pipeline` + `default_deps()` with `UserQueue(inline=True)`; user id `terminal`; default profile, no quiz.
- Arg type: existing file → file, `http(s)://` → link, else instruction.

## Review by T8 (read `reelay/terminal/` + tests + the `cli.py` branch at 66d049c; reran the suite: 326 pass; probed with a fake-deps script)
Good: the terminal really is just another `send` + `UserQueue(inline=True)`; no pipeline logic is copied. Adopt/Skip/Run/Cancel go to `Pipeline.decide` / `Pipeline.confirm`, so owner check, first-tap-only and the strict `clone_command` apply unchanged. Nothing calls `get_bot_token`, no token is printed, and `explain()` never echoes the raw error or advises bypassing certificate checks. `plain()` strips ESC and other control chars, so a hostile transcript can't drive the terminal.
- **FIX 1: only the last report's choices can be answered.** `_Terminal.send` does `self.choices = list(reply.buttons)`, so with 2–3 candidates each report prints `1) Adopt  2) Skip` but earlier reports' buttons are overwritten. Probe: 2 candidates, input `1` → only candidate **b** was adopted; **a** can never be answered, and the loop ends after one answer. Fix: keep a list of pending button sets (print a label like "a: 1) Adopt 2) Skip", or ask once per report in order), and loop until all are answered or the user presses Enter. Add a test with two candidates.
- **FIX 2: exit code is 0 after a failure.** `run_try` returns 0 even when the video couldn't be fetched (network error, download failure) or the adapter refused. Scripts and `reelay doctor`-style checks can't tell. Return 1 when the job ended in an explained network error or a `VideoError` (e.g. a flag set by `send`/`guard`). Test: `load_error = socket.gaierror` → rc 1.
- **NIT 1: `reelay try "check https://…"`** is classified as an instruction (the URL regex needs the whole arg to be one link), but the bot would make that a VIDEO job (`message_to_job` finds the link anywhere). Either reuse `reelay.bot.message_to_job` for the split or say in USAGE that the link must be alone.
- **NIT 2: output order for Run it.** `Pipeline.confirm` runs the job inline, so the adapter result prints before "Running it." Cosmetic.
- **NIT 3: indirect config read.** `default_deps()` (mine) calls `load_config()` for `allowed_projects`; the terminal code itself never reads `config.toml` or the token. A broken file prints the `ConfigError` text (path + TOML position, no contents). Fine, just so the claim in the brief is accurate.
- **NIT 4: edge case in cleanup.** A video file typed by the user under `<tmp>/reelay-*/` would have its folder deleted by `Pipeline._remove_download` (it only expects the bot's own downloads). Unlikely; a note in `runner.py` or copying the file would avoid it.
- **NIT 5: a network error inside `run_trial` or a clarifying question.** The trial path prints "sandbox crashed" instead of the host sentence (the `_NET_MARK` swap only covers the generic job/adapter message); and a router clarification can't be answered in a one-shot command. Both fine for v1, worth a line in the docs.
- **NIT 6:** `plain()` doesn't strip bidi overrides (U+202A–202E, U+2066–2069), which a claim text could use to reorder what the user reads. Add them to `_CONTROL`.
Verdict: **no BLOCKER, 2 FIX, 6 NIT.** Not signed off until FIX 1–2 are done.
