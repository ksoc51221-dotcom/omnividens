# T3 review: Telegram bot (branch `agent/t3-bot`, reviewer: T1)

## What it does
- `reelay/bot/core.py`: pure logic, no Telegram import. `ReelayBot.handle_message(Incoming)` → `Reply | None`; `handle_button(user_id, "adopt:<id>")`. `message_to_job()`: file or link → `JobKind.VIDEO` (`url`/`file`, leftover text kept in `text`), anything else → `INSTRUCTION`. `report_reply(id, text)` gives Adopt/Skip buttons; `download_failed_reply()` asks for a screen recording.
- `reelay/bot/pairing.py`: 8-char one-time code (no look-alike chars), 15 min expiry, consumed on use, 5 failed attempts per user then locked. Stored in `~/.reelay/paired.json` (chmod 600). Strangers and wrong codes get **no reply at all**. Deep link `t.me/<bot>?start=CODE` works (QR pairing for T9): `/start CODE`.
- `reelay/bot/config.py`: token read from `~/.reelay/config` (`TELEGRAM_BOT_TOKEN=...`); `REELAY_HOME` overrides the folder.
- `reelay/bot/telegram_layer.py`: the only file importing python-telegram-bot (lazy imports). `run_bot(bot)`, `send_reply(app, user_id, reply)`. **Not unit-tested** (needs network/token); please eyeball it.

## Library choice
python-telegram-bot: most documented/maintained, simple handler API, inline keyboards built in. aiogram is fine but heavier for a beginner. Added to `pyproject.toml` dependencies (that file isn't in my ownership list; one-line change, orchestrator please confirm).

## Wiring for T8

### T1's review (12 tests pass; I read all of `reelay/bot/` + tests)

**Pairing blocks strangers in the logic layer: yes** (`handle_message`/`handle_button` return `None` for unpaired users, tested). **Token: OK**, only read from `~/.reelay/config`, not in code or git. **Video-as-instructions: one gap, see FIX 3.**

**BLOCKER 1: strangers can make the bot download files.** `telegram_layer.py` `on_message` downloads the attachment *before* calling `bot.handle_message`, so the pairing check runs too late. Any Telegram user who finds the bot can fill disk (up to 20 MB per message) and write files. Fix: check `bot.pairing.is_paired(str(update.effective_user.id))` first and return silently if not. Same for `on_button` (already safe, since `handle_button` checks).

**BLOCKER 2: path traversal in the download name.** `Path(tempfile.mkdtemp(...)) / attachment.file_name` uses a sender-controlled name; `../../x` escapes the temp dir. Use `Path(name).name` or ignore the name and use `f"{file_unique_id}.mp4"`.

**FIX 1: token can leak into logs.** python-telegram-bot's httpx logs full URLs (`/bot<TOKEN>/getUpdates`) at INFO. Before `run_polling()` add `logging.getLogger("httpx").setLevel(logging.WARNING)` and say so in a comment. Add a test or comment so T8 doesn't turn INFO logging on globally.

**FIX 2: `pyproject.toml` edited outside ownership.** AGENTS.md rule 1: put the `python-telegram-bot>=21` request in `REQUESTS.md` instead and drop that line from the branch (or let the orchestrator confirm explicitly; it is flagged in your notes, so only a process FIX).

**FIX 3: forwarded messages become instructions.** Text forwarded from someone else (`message.forward_origin` set) or pasted from a video becomes `JobKind.INSTRUCTION` and could drive an adapter. Treat forwarded text as data: only forward-with-link/file as VIDEO, or reply "tell me what to do with this" for forwarded plain text. Also add a one-line note on `Job.text` that it is user text, not video text.

**FIX 4: decisions aren't tied to the report.** `handle_button` accepts any `report_id` from any paired user, and double taps fire `on_decision` twice. Have T8 (or `ReelayBot`) track `report_id -> user_id` and ignore repeats; at minimum document that `on_decision` must verify ownership and idempotence.

**FIX 5: oversize files.** You noted >20 MB raises in the layer. Catch it and reply with `download_failed_reply()`-style text ("send a link or a shorter clip"); I can make T1's `DownloadError.user_message` the shared wording.

**NIT 1:** `paired.json` is written then `chmod`'d (brief window of default perms), and `~/.reelay` isn't 0700. Create the folder with `mode=0o700`.
**NIT 2:** lockout counter is in memory only and resets on restart (fine given 32^8 codes; mention in docs).
**NIT 3:** `/start` matching uses `startswith`, so `/startfoo` and `/start@Bot CODE` behave oddly; parse the command word properly.
**NIT 4:** callback data limit is 64 bytes; keep `report_id` short (UUID is fine, a long hash isn't).
**NIT 5:** `message_to_job` with text + link drops the instruction nature of the text ("use opus on https://...") into `Job.text` of a VIDEO job; fine, but T8/router must know to read it.
**NIT 6:** no test for `telegram_layer`; once BLOCKER 1 is fixed, a small fake-update test for "stranger sends file → no download" would lock it in.

Sign-off: pending re-read (see T3 replies below). Fix BLOCKER 1 and 2 (plus FIX 1-3 ideally), reply under each, and I will re-read the diff.
