# T20 review: one fact-check + one report per candidate (cloud path)

Branch `agent/t20-reports`. Reviewer: T8.

## What it does
- `reelay/core/reports.py` (new, shared with local mode later): validates each routine report, builds the plain-text message (sections 1-4), and decides the only place a clone line may exist (`adopt_line`).
- `reelay/cloud/report.py`: sends one short fact-check message, then one report per candidate (max 9, video order), each with its own `adopt_line`. A relay error (daily budget) stops the loop and one line names what was left out.
- Adopt rule: type `skill`/`mod` AND safety `YES` AND exact owner/repo matches the URL AND not name-only. Unknown/missing type, apps, UNSURE, NO: read-only, no clone line. NO says "I recommend Skip". (Stricter than the old Adopt-with-warning for high risk: a decision to confirm.)
- Usage: tokens labelled `measured` only if the routine says so for a positive count; the default is `estimate`. Setup minutes and money are always "estimate".
- Section 3 only names a project that is on the owner's list; empty list gives the "/projects" line; no match gives "No fit".
- Relay: `/projects` (owner only, before any routine call), own KV key, `GET /api/profile` returns `projects`, `PUT` ignores it, `MAX_REPORTS_PER_DAY` (default 30) for sends with `report: true`.
- Per-candidate state: `/api/send` already stores each clone line under a random id; tested that two reports get different ids and one tap returns only its own line.

## Gate (computed in `report.py`, not from model output)
- Safety: `find_problem` on the clone at `/tmp/trial/<owner>__<repo>` (None -> clean/YES, a reason -> NO, no clone or error -> UNSURE). The model can only lower it. `skill-scan` is not used (not installed in the VM).
- Identity: confirmed only if the exact owner/repo is in `bundle.github_links`/caption/transcript/message text, or typed by the owner in `/report`. On-screen text is not recorded in `bundle.json`, so it does not count.
- Type: `skill` needs `SKILL.md` (root, `skills/*/`, `.claude/skills/*/`); `mod` needs `.claude-plugin/plugin.json`, `hooks/` or `commands/`. Otherwise read-only, saying why.
- Left-out: named as owner/repo with `/report owner/repo` (new run, uses usage); relay validates the format; the daily cap mid-run names what was not sent.
- Run log line printed by `report`: candidates, reports, messages, seconds (no token counts).

- Code detection (`find_code`): `hooks/` or `scripts/` dirs, script extensions, manifests mentioning `"hooks"`. Clean scan + code = UNSURE with fixed text + up to 5 sanitised paths. `ADOPT_ALLOWED_WITH_CODE` (default True) is the one switch; tests for both settings. Identity UNSURE, failed clone, too-big, scan error, model NO stay read-only.
- Behaviour change: Adopt for a code-free skill now needs only model != NO plus the deterministic YES (it still needs model YES to *show* YES). Unchanged from before for YES; the model's "UNSURE" never gave Adopt and still doesn't.
- Lookalike-domain fix, owner rule `[A-Za-z0-9-]+` (`_REPO`, `_GH_LINK`, `_GH_BARE`, relay `ADOPT_RE`, `/report`), dedupe by lowercase owner/repo, bidi strip, `.GIT`, "too big to scan" UNSURE, retry cap on the relay budget loop (503), `RelayError.status` instead of string-matching 429.
