# T20 review: one fact-check + one report per candidate (cloud path)

Branch `agent/t20-reports`. Reviewer: T8.

## What it does
- `reelay/core/reports.py` (new, shared with local mode later): validates each routine report, builds the plain-text message (sections 1-4), and decides the only place a clone line may exist (`adopt_line`).
- `reelay/cloud/report.py`: sends one short fact-check message, then one report per candidate (max 9, video order), each with its own `adopt_line`. A relay error (daily budget) stops the loop and one line names what was left out.
- Adopt rule: type `skill`/`mod` AND safety `YES` AND exact owner/repo matches the URL AND not name-only. Unknown/missing type, apps, UNSURE, NO: read-only, no clone line. NO says "I recommend Skip". (Stricter than the old Adopt-with-warning for high risk: a decision to confirm.)
- Usage: tokens labelled `measured` only if the routine says so for a positive count; the default is `estimate`. Setup minutes and money are always "estimate".
- Section 3 only names a project that is on the owner's list; empty list gives the "/projects" line; no match gives "No fit".
- Relay: `/projects` (owner only, before any routine call), own KV key, `GET /api/profile` returns `projects`, `PUT` ignores it, `MAX_REPORTS_PER_DAY` (default 30) for sends with `report: true`.
- Per-candidate state: `/api/send` already stores each clone line under a random id; tested that two reports get different ids and one tap returns only its own line.
