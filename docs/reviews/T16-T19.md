## T19: friendly rate-limited error handler

Checked and OK:
- **No token in normal output.** Without `--debug` the handler prints only fixed text (`CERT_HELP` / `NET_HELP` + " Retrying…") or `Something went wrong (<TypeName>)`. The error text is never printed. The tests feed it a token-shaped string and assert it is absent.
- **Debug output is scrubbed.** `scrub_token` hides `\d{6,}:[A-Za-z0-9_-]{20,}`, which matches real bot tokens and the `/bot<token>/getUpdates` URL form. Debug is not rate limited, as intended.
- **No VPN or bypass advice.** Wording reuses `explain_network_error` ("another network or a phone hotspot"); the test asserts no "vpn" / "disable".
- **Really rate limited.** `time.monotonic` clock; the first error prints at once, later ones are dropped until 60 s have passed. The test advances the clock and checks 5 errors give 1 line, then 2 after 61 s.
- **The flood stops.** `Application.run_polling` passes its own `error_callback` to the updater, which sends polling `NetworkError`s to the registered handler. In that path PTB only logs at DEBUG while retrying, so no default traceback is logged.

Findings:
- **FIX 1: invalid-token traceback still reaches stderr.** PTB's network loop does `_LOGGER.exception("... Invalid token. Aborting retry loop.")` (`telegram/ext/_utils/networkloop.py`, the `except InvalidToken` branch) before re-raising. `InvalidToken`'s message contains the full token, and `basicConfig(level=WARNING)` prints that traceback to stderr, before `serve()` prints `TOKEN_HELP`. This predates T19 and the handler can't see it, but it defeats the "never prints the bot token" goal. Fix: in `main()`, unless `--debug`, put a `logging.Filter` on the `telegram` logger that runs `scrub_token` over the message and exception text, or drop records at ERROR and above from `telegram.ext` and rely on `serve()`'s message. I did not trigger this live.
- **NIT 1:** the 60 s limit is global, not per error kind. A `Conflict` or other error arriving within 60 s of a network line is hidden. Cheap fix: keep one `last` per `type(error)`.
- **NIT 2:** `Conflict` and `InvalidToken` raised through the handler print the generic "Something went wrong (Conflict). Run with --debug" even though `CONFLICT_HELP` / `TOKEN_HELP` exist. Reuse them.
- **NIT 3:** `--debug` is not in `HELP` in `reelay/installer/cli.py` (`reelay run --debug` works, since `argv[1:]` is passed through).
