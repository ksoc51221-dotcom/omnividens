# T34: three low-risk fixes from the code analysis

Branch `agent/t34-lowrisk`, from `main` at `c7c3316`. Findings 1, 3 and 6 of `docs/reviews/code-analysis.md`. Finding 7 and everything labelled AFTER are left out.

## What changed
1. **Timeouts** (`relay/app.ts`): 15 s on `tg()`, 30 s on `fireRoutine`. A timeout takes each call's existing failure path, so nothing new can throw out of the webhook. A stalled routine gives the existing "routine unreachable" message.
2. **`/report owner/repo.git`** (`relay/app.ts`): refused any case with the existing format reply, before any rate slot or run.
3. **Local bot links** (`reelay/bot/core.py`): now uses `first_url` from `reelay/cloud/job.py`.

## Can a slow fire be retried into a double fire?
No automatic path does this. Each is covered by a test with a fake that never answers.
- **Webhook:** the update is marked seen at `relay/app.ts` before the fire, so a Telegram retry returns early.
- **Mac job:** the row is claimed and deleted before the fire, so sweeps find nothing and a repeated upload gets 409.

**One gap remains, and the owner can trigger it.** If `/fire` takes over 30 s but still starts, the owner is told it couldn't start. Sending the link again then gives two runs, because it's a new update and `/fire` has no idempotency key. The real `/fire` time has not been measured.

## Behaviour to know
- With every Telegram call stalled, a webhook can take up to 15 s per message sent, plus 30 s for a stalled fire. That is now bounded; before, it had no limit.
- A sweep can fire ready Mac jobs one after another, so the 30 s limit applies per job.
- `HTTPS://` links now reach the local video path, where they used to be treated as instructions. `urlhost` in `reelay/core/pipeline.py` only matches lowercase, so its message says "unknown host" for them. Cosmetic.
- A trailing `(` and `)` stay in the note: `watch (link)` gives the note `watch ()`.
