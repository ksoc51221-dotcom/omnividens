# T28: five leftover bugs

Branch `agent/t28-leftovers`, based on `agent/t27-bugfixes`. Each fix has a test that fails without it.

## What changed
1. **Missing `verdict.json` no longer throws away the frames** (`reelay/cloud/report.py`). `bundle.json` and `verdict.json` are now read separately, so a 30-frame video no longer says "No frames were extracted".
2. **A hung Whisper model can't keep the Mac process alive** (`reelay/cloud/mac_worker.py`). The model now runs in a daemon thread, so when it times out the process really exits. Test runs it in a subprocess: 1 s timeout, model sleeping 8 s, process must end in under 5 s.
3. **The public status page can't re-point the webhook** (`relay/app.ts`). The webhook is set only to the new optional `PUBLIC_URL` env var (must be https), and only when the page is served from that address. Anywhere else, or without it, the page only reads Telegram's state and changes nothing. **A deployment works without `PUBLIC_URL`**: a webhook that's already set keeps working across a redeploy, because no code path sets or deletes it unless `PUBLIC_URL` is set. Setting a webhook for the first time, or moving one, is the explicit step: add `PUBLIC_URL`, then open the production page once. `docs/SETUP-CLOUD.md` and `relay/README.md` updated.
4. **Round video notes and photos get a reply** (`relay/app.ts`). `video_note` is handled like a video and starts a run. A photo with no caption gets one line ("I can't read photos yet...") and starts no run.
5. **Link matching.** The relay's `/report` owner now matches `[A-Za-z0-9][A-Za-z0-9-]*`, so `/report a_b/c` is refused up front instead of wasting a run. `_GH_BARE` in `reelay/cloud/job.py` no longer matches `github.com/o/r` after a `/`, unless that is the `//` of `https://` or `http://`.
