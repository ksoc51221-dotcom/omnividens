## What it does
- `Deps` holds every outside call (`load_video`, `fact_check`, `run_trial`, `route`, `run_adapter`, project default, decision log). Tests pass fakes for all of them; `__main__.default_deps()` builds the real ones.
- `PipelineBot(ReelayBot)` is the fast side: first contact (pairing) starts the quiz; `/vibe /profile /forget /quiz`; buttons `adopt|skip|run|cancel|quiz|vibe`. Unknown `/commands` never reach the router.
- `Pipeline` is the slow side, run by `UserQueue` (shared thread pool, one job at a time per user, max 5 waiting; one user's slow video never blocks another).
- Video job: `load_video` → `fact_check(bundle, profile)` → plain-text verdict → up to 3 × `run_trial` → one report per trial with Adopt/Skip. Progress lines: watching / fact-checking / testing in sandbox (i/n).
- Instruction job: `route` → clarifying question (the next message is joined to it) or a confirm card (task, project, skill, model, effort) with Run it / Cancel → adapter → result.
- Trust receipt (`🧾 Saw · Checked · Ran · Refused`) ends the verdict, every trial report, the adopt note and every adapter result.
- Errors: `VideoError.user_message` (download → screen recording, too long, unreadable), sandbox crash, adapter refusal, `ConfigError`, anything else → "Something went wrong (ErrorName)" with no details.

## Design choices / tradeoffs
| Choice | Why | Cost |
|---|---|---|
| Subclass `ReelayBot`, override `handle_message`/`handle_button` | no edits to `bot/` needed; its pairing + job rules stay | depends on its method names |
| Quiz questions pushed via `send`, not returned | the Telegram layer's button handler can't attach buttons to a reply | old buttons stay visible; stale taps are ignored |
| Single allowed project becomes the default project | friendlier; the confirm card shows it | with 2+ projects the user must name one |
| Clarification answers are joined to the earlier message | otherwise the question is useless | in memory only, lost on restart |
| Profile module used for real (tmp `REELAY_HOME`) in tests | it is pure local disk | not a fake |

### T3's review (read `reelay/core/pipeline.py` + `__main__.py` at 25f6f46; reran the suite: 198 pass)

Good: owner check + first-tap-only in `decide`, plain text, `source` only from `job.file`/`job.url`, per-user queue, no installs, token never logged. Link-preview request done on branch `agent/t3-previews` (commit in `../reelay-t3c`; all three send sites; bot tests pass).

**BLOCKER 1: `adopt_text` builds a copy-paste shell command from untrusted text.** `git clone {shlex.quote(candidate.url)} ~/.claude/skills/{name}`: `candidate.url` comes from the video/fact-check model and nothing in factcheck/sandbox validates it. `shlex.quote` stops shell injection but not git options or odd transports: a url like `--upload-pack=touch /tmp/x` is quoted but still parsed by git as an option; `ext::…` / `file://` / `git://` URLs are also accepted by `git clone`. The user pastes this line into their terminal, so it is the one place a video could cause code execution. Fix: only print the clone line if `url` matches `^https://[A-Za-z0-9.-]+/[\w./~-]+$` (no spaces, no leading `-`), and write it as `git clone -- <url> <dest>`. Otherwise use the "open the link and read the README" branch. Add a test with `--upload-pack=…` and `ext::sh -c …` URLs expecting no `git clone` text.

**FIX 1: downloaded file leaks when the queue is full.** `Pipeline.submit` returns early ("I still have a few things queued") without calling `_remove_download(job.file)`, so each rejected upload leaves a `reelay-*` folder (up to 20 MB each) in the temp dir. Remove the file in that branch. Test: fill the queue, submit one more with a file, assert the folder is gone.

**FIX 2: forwarded text can answer a quiz question.** `handle_message` feeds any text to the quiz when `_quiz_wants_text`, including `msg.forwarded` text, which then lands in the profile goals (and later in fact-check prompts). Skip the quiz branch when `msg.forwarded`.

**NIT 1:** `bot.pipeline.queue.shutdown()` waits for running jobs after Ctrl+C (a slow video can hang exit for minutes); consider `shutdown(wait=False, cancel_futures=True)`.
**NIT 2:** `Pipeline._unclear` is popped from the event-loop thread (`/forget`) and from worker threads; harmless today, but use `self._lock` if it grows.
**NIT 3:** a message dropped because `TelegramSender.app is None` (before startup) is silent; fine.

Sign-off: not yet. BLOCKER 1 must be fixed; FIX 1-2 should be.
