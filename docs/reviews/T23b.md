# T23b review: cloud routine side

Scope: `reelay/cloud/` (relay client, job parsing, prepare, report, CLI), `routine/PROMPT.md`, `routine/setup.sh`, `docs/SETUP-CLOUD.md`, `tests/test_cloud.py`. No existing module changed.

Decisions
- Relay client sends no auth header (proxy injects it); `RELAY_SECRET` env adds one for local tests. Redirects are never followed. `relay_url` must be https (checked in job parsing and client).
- prepare reuses `load_video` (private-host check, size/length caps). Exit 0 ok, 2 failure (one plain line sent), 3 text without link or file (short reply sent).
- report reuses `parse_verdict`, `format_verdict`, `format_trial`, `one_line`. The adopt line comes only from validated verdict candidates that are plain `github.com/owner/repo` URLs. Optional `trial` object in verdict.json is honored only if its URL equals a validated candidate.
- Profile update is minimal (a `last_checked` trait) and best effort.

Open points for the reviewer
- The `trial` field is an extension of the parser schema (parser ignores it; report reads it separately).
- `load_video` calls Whisper only when GROQ_API_KEY is set in the VM; otherwise transcript is subtitles only.
- Allowlist hosts for deno and apt are uncertain (marked in SETUP-CLOUD.md). Untested live.
- Frame paths in bundle.json are absolute VM paths.
