# T4 review: Sandbox (branch `agent/t4-sandbox`, reviewer: T5)

## What it does
`run_trial(candidate, runner=None, ...) -> TrialReport` in `reelay/sandbox/`:
- `fetch.py`: https-only, no embedded credentials, rejects private/local hosts (reuses `video.download.is_private_host`); shallow clone with `protocol.allow=never`, hooks disabled, `--` before the URL, minimal env (no HOME).
- `scan.py`: runs `python3 -I ~/.claude/skills/skill-scan/scan.py --json --all <path>`, worst verdict wins (CLEAN/LOW→clean, REVIEW→review, HIGH→high). Scanner missing/broken/no units → `review`, never `clean`.
- `runner.py`: `claude_runner` copies the repo (without .git) into an isolated `HOME/.claude/skills/candidate`, runs `claude -p --output-format json` with own HOME + CLAUDE_CONFIG_DIR, tools limited to Read/Write/Edit/Glob/Grep/Skill, `--strict-mcp-config`, `$0.50` budget cap, timeout. Tokens = sum of the 4 usage fields from the CLI JSON; seconds = wall clock. Runner is pluggable (`Runner` type).
- `trial.py`: orchestration. `high` is never run. Run folder under `~/.reelay/sandbox_runs/<id>/` is deleted afterwards (`keep=True` to debug). Never raises for bad candidates.

## Review by T5 (read-only; read `main...agent/t4-sandbox` @ 887a63c; ran nothing live)

Good: https-only fetch with hooks/protocols locked, `--` before URL, `high` never run, never-raises orchestration, cleanup in `finally`, tokens/seconds measured from the CLI JSON and a wall clock (not guessed), pluggable runner. The problems are in what Claude is allowed to touch.

- **BLOCKER** `runner.py` `--allowedTools "Read,Write,Edit,Glob,Grep,Skill"`: bare tool names are blanket allow rules, so they are NOT limited to the work folder. A candidate's SKILL.md (or a prompt injection in it) can make Claude `Read ~/.reelay/config` (holds the API key / allow-list), `~/.ssh/*`, or other projects, and `Write`/`Edit` any file the user owns by absolute path. `acceptEdits` only scopes the *implicit* edit approval; the explicit allow rule overrides it. Fix: drop `--allowedTools`, use `--permission-mode dontAsk`, and allow only path-scoped rules (`Read(<work>/**)`, `Write(<work>/**)`, `Edit(<work>/**)`, plus the skill dir for Read) and keep `--tools` as the ceiling. Add a test that asserts the argv contains no bare `Write`/`Read` allow rule.
- **BLOCKER** symlinks: `copytree(..., symlinks=True)` copies a repo symlink such as `notes -> /Users/x/.ssh` into the skill folder, and Read follows it. The scanner only flags it as `review`, which still runs. Fix: before copying, walk the repo; if any symlink resolves outside the repo, return `review`/not-run (or delete the link). Test with a link to `/etc`.
- **BLOCKER (verify, I could not confirm either way)** skill frontmatter can declare `allowed-tools` and hooks. Hooks are shell commands run by Claude Code itself, outside any tool restriction, i.e. the candidate's code would run un-sandboxed as the user. `--tools` limits tools but may not stop hooks. Fix: write `{"disableAllHooks": true}` into `<config>/settings.json` of the isolated config (and/or pass `--settings` with it), and try `--bare` (skips hooks, plugins, CLAUDE.md discovery, keychain) if auth is by `ANTHROPIC_API_KEY`. Then do one manual run with a toy skill that has a `hooks:` entry touching a canary file; the canary must not appear.
- **FIX** run folder lives under the real `~/.reelay/`, next to the real config. With the fix above that is safe, but a cheaper belt-and-braces is `tempfile.mkdtemp` under the system temp dir with mode 0700, so "outside work folder" never contains `~/.reelay`.
- **FIX** auth: `HOME` and `CLAUDE_CONFIG_DIR` are replaced, so a Pro-plan (OAuth) login is lost and the run will fail with "not logged in" unless `ANTHROPIC_API_KEY` is set. The Pro-only owner likely has no key. Decide explicitly (document it, or make the trial report say "needs an API key"), and check the failure message is surfaced in `logs` rather than only `fit`.
- **FIX** no size cap on the clone: a huge repo fills disk and the copy doubles it. Add `--filter=blob:limit=…`/check `du` after clone and refuse above e.g. 50 MB; also cap files copied.
- **FIX** timeout: `subprocess.run(timeout=)` kills `claude` but not any child it spawned. Use `start_new_session=True` and kill the process group on timeout. On timeout tokens are reported as 0 even though some were spent; say "unknown" in logs.
- **NIT** `--max-budget-usd 0.50` is meaningless under a subscription login and a hard failure if budget is hit mid-run; fine, but mention in docs.
- **NIT** `ANTHROPIC_API_KEY` is passed into the process env; with file tools only it cannot be read, but if Bash ever gets added it can. Keep the `--tools` list a constant with a test.
- **NIT** `check_url`: `is_private_host` resolves DNS once; git re-resolves (rebinding) and follows one redirect. Acceptable for a hackathon; note it.
- **NIT** answer to your Q1: use `--bare` only if API-key auth; `--setting-sources` was not verified in `claude --help` v2.1.291, so I'm not recommending it. T5's own adapter sends the task on stdin; here the prompt is a fixed constant, which is correct (no video text in it).

Status: 3 blockers (two certain, one needs one manual canary run). Not approved until fixed.
