Two optional nits, not fixed:
- `reelay/core/reports.py` `_BINARY_MAGIC` / `_looks_executable`: the 2-byte `MZ` magic flags a text file starting "MZ" (such as `AUTHORS.txt`), giving UNSURE plus a code warning. It fails safe. Fix: also require the `PE\0\0` header, or skip text extensions.
- `reelay/video/frames.py` `_SHOWINFO_TIME`: exponent form `1.11111e-05` would parse as `1.11111`. Not reproduced with real ffmpeg and not a regression. Fix: allow `(?:[eE][-+]?\d+)?`.

## What it fixes
1. `/report` always failed: `routine/PROMPT.md` asks for `{"reports": [...]}` but `extract_json` required a `summary`. `report.py` now looks for the `reports` object first. A video whose summary went missing also keeps its reports.
2. Any owner text started a routine run (`/start`, `hello`, `/vibe`). The relay now answers those itself: no run, no rate slot.
3. Uploads over 20 MB and non-video files started a run that could not work. The relay now answers them directly. If the caption has a link, the run uses the link.
4. Too-long and too-big videos got "no clear reason": yt-dlp prints those skips on stdout and the code read only stderr. Both streams are checked now, so `TooLongError` and the Mac's `too_long` reason work.
5. Video metadata could crash frame extraction (non-UTF-8 title) or fake scene cuts (`pts_time:` in a title). Tool output is decoded with `errors="replace"`, and only `Parsed_showinfo` lines are parsed.
